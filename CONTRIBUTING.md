# Contributing

Thanks for helping! Read [docs/github/CHEATSHEET.md](docs/github/CHEATSHEET.md) and [docs/project_management/PROCESS.md](docs/project_management/PROCESS.md) first.

- Open an issue before large changes. Branch from `main`, keep PRs small, run `npm test`.
- **Sign off your commits** (`git commit -s`): this certifies the [Developer Certificate of Origin](https://developercertificate.org/).
- The project is licensed **AGPL-3.0-or-later**. The maintainers may also offer it under a commercial licence (see [docs/economy_finance/LICENSING_STRATEGY.md](docs/economy_finance/LICENSING_STRATEGY.md)). Dual licensing requires that contributors grant that right: a CLA (or equivalent) is **not in place yet** and must be decided before external contributions are merged. Until then, ask before opening a PR.
- Security issues: do not open a public issue; see [docs/eu/cra/VULNERABILITY-POLICY.md](docs/eu/cra/VULNERABILITY-POLICY.md).
